scaleway-manager

Forge report — web UI hosted in a Kubernetes cluster, driving Scaleway through scaleway-operator custom resources.

Outcome

The idea is specific enough to start. Purpose, staging, control model and a handful of hard rules are locked. Design, forms and the Scaleway-connectivity check are deliberately left open.

What it is

A web service running in a (usually throwaway kind) cluster. Its backend creates, reads, updates and deletes custom resources; scaleway-operator, and later KRO, turn them into real Scaleway infrastructure. The UI is the master on board.

Stages, one after the other

  1. Test scaleway-operator.
  2. Test quick deployment of objects into Scaleway.
  3. Test compositions of infrastructure objects with KRO, which could lead to a landing zone.

Locked decisions

  • The cluster is the control plane; every managed Scaleway resource is a CR. Existing infrastructure is taken over by writing matching CRs (the operator adopts by name or tags).
  • Delete has no confirmation and no "forget" gesture. It can break things, on purpose.
  • Reach: once a namespace can manage a Scaleway project, the UI does whatever it wants there.
  • The UI fills gaps in the cluster, it does not only report them.
  • kind is disposable; durable state is YAML export and later re-import.
  • At least one non-default namespace is needed before talking to Scaleway; default, kube-system, kube-public, kube-node-lease are never valid support. Fixed list.
  • Forms are hand-written per resource type, iteratively.
  • Edit only on resources that are Synced.

Rejected, and why

  • First slice: list Instances, create form, delete. Too small; ignores the operator's real workflow and the cluster check.
  • Guided wizard creating namespace + NamespaceRole + Secret. Unbalanced.
  • Two-section home page. Only an idea; design is not done.
  • Showing Scaleway resources that have no CR. Meaningless in this model: no CR, no operator.

Weak points that survived

  • open How to ensure the cluster can talk to Scaleway. The operator health endpoint covers the global token only, not per-namespace credentials.
  • open Hand-written forms vs. KRO-composed CRDs the UI has never seen (stage 3).
  • open What each namespace section displays; multiple Scaleway accounts (minor).
