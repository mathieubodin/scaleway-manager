What you validate

A test-only fake operator that mimics scaleway-operator-v0.1.15 exactly, so that automated tests can move custom-resource status without Scaleway, plus internal/kube, the only Kubernetes client, and internal/kube/kubetest, the fake API server of the Go tests. It unblocks #53 (automated-test kind cluster) and #15 (behavior diff).

This page helps you understand; the reference files are what you validate or invalidate.

1. What changes for the user

  • Nothing visible in the UI: the fake never reaches the release image, Dockerfile, chart or release workflow.
  • Automated tests can create an Instance, LoadBalancer or ScalewaySecret and see it go through the real operator's steps: finalizer, Syncing, Synced, with the real status values and messages.
  • A test forces a Scaleway-side cause with the annotation fake.scaleway-manager.test/outcome (NotFound, Error, Locked, Revoked) and sees the effect the operator writes for that kind; a cause a kind cannot have is refused with a visible Error.
  • The fake checks what the operator checks and can read: NamespaceRole, read-only role, project-id annotation, spec lists, source configured, region.
  • Steps are FAKE_OPERATOR_STEP_DELAY apart (default 2s), so a test and a human can see each state.
  • The fake refuses to start where the real operator runs, and has no access to Secrets.

2. Scope and non-goals

In scope: cmd/fake-operator; internal/kube (URL builder over the AD-2 closed list, list, get, merge patch, status patch); internal/kube/kubetest; cmd/fake-operator/Dockerfile and make build-fake-operator-image; raw manifests and RBAC in tests/cluster/fake-operator/; Go tests.

Non-goals:

  • The automated-test kind cluster, CRD installation, loading the image and the real-cluster smoke test: #53.
  • Watch, create and delete in internal/kube: they come with the server.
  • The AD-2 discovery and review endpoints of the readiness screen: the readiness feature adds them to the same URL builder.
  • RDB and any kind absent from v0.1.15.
  • Mimicking Secret-dependent checks, last_synced_resource_version, FinalizerRemovedWithoutScalewayDelete or the circuit breaker; the Secrets feature will need @manual scenarios for these.
  • Gherkin scenarios and steps.

Constraints: contract scaleway-operator-v0.1.15 with CRDs 0.1.14, read only at that tag; Go standard library only (AD-1); no Scaleway call (AD-2); internal/kube reads no token itself; every cause applies on every pass while present, with no memory.

4. Decisions taken during Define

Forge (_bmad-output/forge/fake-operator/forged-idea.md), architecture update and the answers of define-notes.md:

  • All outcomes from the start, per kind, only where the operator produces them; AD-9 corrected before the spec.
  • The annotation names the Scaleway-side cause, never a sync_state; state model with no memory; NotFound stays cleared while present.
  • Contract: release scaleway-operator-v0.1.15, CRDs 0.1.14; the first analysis read a stale local branch, every fact was re-checked at that tag.
  • Polling, no watch; internal/kube reads no token; no access to Secrets; AD-2 gained apps/v1 deployments, list only.
  • P1: explicit projected token volume at /var/run/secrets/kubernetes.io/serviceaccount, automount off.
  • P2, P3: NamespaceRole and Namespace read errors and Revoked before the finalizer follow the operator.
  • P4: a refused cause never blocks deletion.
  • P5: the message annotation is ignored for NotFound.
  • P6: the read-only role wins over a cause before creation.
  • V1: a ScalewaySecret writes Syncing and Synced in one pass, as the operator.
  • R1: the operator version is named in AD-9; R2: follow-up #53 created, blocking #15; R3: each kubetest test cites its documentation; R4: exit 1 beside a real operator Deployment; R5: complete AD-2 URL builder, operations limited; R6: /healthz with a liveness probe.
  • Details D1 to D14, R7 to R10 validated as one list (messages, empty outcome, pass scheduling, SIGTERM, kubetest extras, guard test in tests/make, migration "no impact").
  • Research: none needed.
  • Spec-lint: three rounds; criteria reworded twice; after round 3 the substantive ambiguities were fixed and the form of tests left to the story specs and cold-start.

5. Risks and open points

  • Pre-mortem R1: drift from the operator; answered by the named version, any release change means reviewing the fake.
  • Pre-mortem R3: kubetest drifting from the API server; answered by cited documentation in #42 and a real-cluster smoke test in #53.
  • Pre-mortem R7: Secret-dependent checks are not mimicked; covered only by @manual scenarios of the Secrets feature.
  • Pre-mortem R10: frozen Go tests of different stories sharing internal/kube or kubetest; the plan avoids it where it can, otherwise the rules of #48 and #50 apply.
  • Assumption: current_version starts at 1 on a new secret (Scaleway numbering, not operator code).
  • Open: the form of tests (one Test function or t.Run subtests, exactly or at least one) and which failure a test injects: left to the story specs and cold-start.
