What you validate

How #41 is built: the spine layout for the Go code, four stories built as a trunk of three (server, image, chart) then one leaf (process files), with the contracts each story relies on.

This page helps you understand; the reference files are what you validate or invalidate.

Chosen approach

Spine layout: internal/server holds the handler (AD-8 header middleware around the whole mux, and the routes); cmd/scaleway-manager holds configuration, listening, signals and logs through a run function whose shutdown delay is injected (10 s in production), so Go tests drive the lifecycle in-process. Later features add routes to internal/server without moving code.

Set aside:

  • Everything in cmd/: fewer files now, but the first feature would move the handler to internal/server, a refactor planned from the start.
  • Process-level lifecycle tests (real binary, real signals): the shutdown-timeout test would last over 10 s.

Decisions taken in Plan with the author:

  • Go 1.27.2 instead of 1.27.1, for its net/http security fixes; the spec and the spine Stack table follow.
  • net/http internal errors (ErrorLog) go to slog JSON on stdout at level WARN.
  • Default resources: requests cpu: 10m, memory: 32Mi; limits memory: 64Mi; no CPU limit (GOMAXPROCS follows it).
  • docs/development-process.md, scripts/evidence.sh and the sdlc-work deliver reference are updated in #41.
  • helm-unittest 1.2.1 supports Helm 4.3.0: the spec's open question is closed.
  • E1 to E12 (tool pins, routes, signals, Dockerfile args, gofmt check, migration note, no extra linter): validated together, listed in plan.md.

Build order

Trunk, one story at a time (each edits Makefile, pr-checks.yml and prek.toml; story 2 needs story 1's binary), then the leaf:

1 Go server and AD-1 check → 2 Container image → 3 Helm chart → 4 Process files (leaf)

Story 1 has spec_checkpoint (reviewed by the author) and done_checkpoint: the build pauses after it for the author to look at it.

Contracts at each boundary

  • Story 1 → story 2: go build ./cmd/scaleway-manager from the module root produces the static server binary; it embeds web/index.html, reads only LISTEN_ADDR, answers GET /healthz with 200 ok. The Dockerfile builds that package only, not cmd/check-go-mod.
  • Story 1 → stories 2, 3: the Makefile pattern of story 1 (a tool guard per tool, a ## comment on each public target, every target in .PHONY, check extended); one pr-checks.yml job per target, named exactly as the target.
  • Story 2 → story 3: the image listens on the port of LISTEN_ADDR and runs as uid 65532 with a read-only root and no capability; the chart's securityContext matches what build-image exercised.
  • Stories 1 to 3 → story 4: the five target names lint-go, test-go, check-go-mod, lint-chart, build-image; make check runs the first four; build-image needs Docker and runs in CI; the required-check gh api command of the contract.

Story 1

  • What run does when Serve returns an error other than http.ErrServerClosed before any signal: closed after the round, with the author (one ERROR line serve failed, exit 1).
  • How cmd/check-go-mod reports a module with both a require and a non-empty go.sum, and whether it prints to stdout or stderr.
  • The unformatted file of the lint-go criterion must be tracked by git, since lint-go checks git ls-files '*.go'; with no tracked .go file, gofmt -l with no argument reads stdin.
  • The process files and docs/migrations/next/41.md belong to story 4.

Story 2

  • tests/image/check-dockerfile.test.sh and its fixtures are written and frozen at Rails; the builder follows them.
  • A per-attempt curl timeout, so polling stays within 30 s.
  • .dockerignore: *.md or **/*.md; the build works with either.

Story 3

  • The exact wording of the missing-plugin hint of check-helm.
  • Whether the ClusterRoles render rules: [] or no rules key.
  • Story 1's tool guard and prek hook are the pattern to copy once story 1 is merged.

Story 4

  • The job names added by stories 1 to 3 are the five target names; the builder checks pr-checks.yml once the trunk is merged.
