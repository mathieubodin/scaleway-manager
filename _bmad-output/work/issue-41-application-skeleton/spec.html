What you validate

The spec of the smallest runnable scaleway-manager: a Go server, its image and its chart, under the spine's rules (AD-1, AD-3, AD-8, AD-11, AD-12), with the checks that keep those rules true from the first commit.

This page helps you understand; the reference files are what you validate or invalidate.

What changes for the user

  • Today the repository has no application code. After this work, there is a server you can run that answers /healthz and shows a placeholder page saying no feature exists yet.
  • An image runs that server read-only, without any capability, as uid 65532.
  • A Helm chart installs it as exactly one pod behind a Gateway you name; the pod has no Kubernetes API rights.
  • Every PR gets five new checks (lint-go, test-go, check-go-mod, lint-chart, build-image), which become required checks of main right after the merge.
  • #14, #16 and #42 can then start from main.

Scope and non-goals

In scope: go.mod (Go 1.27.1, no require), cmd/scaleway-manager, cmd/check-go-mod, web/index.html, the Dockerfile, the chart charts/scaleway-manager, the make targets, prek hooks and CI jobs. Field-by-field contract: _bmad-output/specs/spec-application-skeleton/skeleton-contract.md.

Not in scope:

  • Coverage, mutation testing and thresholds (#14).
  • A kind cluster or any in-cluster run (#16).
  • Multi-arch builds, cosign signing, provenance attestation, publication to ghcr.io, release versions (#18); the chart stays at 0.0.0.
  • The scaleway-manager-credentials Role in scaleway-system (first feature that writes a Secret).
  • The /api/events HTTPRoute rule (stream feature).
  • Any rule in the two ClusterRoles; any binding.
  • Any Kubernetes API call, login, session or Scaleway readiness check.
  • Rejecting a port below 1024 in the chart.
  • The Go race detector.

Decisions taken during Define

Source: _bmad-output/work/issue-41-application-skeleton/define-notes.md.

  • Forge: #41 ships the minimum executable checks plus CI; coverage and mutation stay in #14.
  • Forge: two empty, unbound ClusterRoles; the credentials Role waits for the first feature that writes a Secret.
  • Forge: HTTPRoute with one rule on /; Gateway name and namespace required.
  • Forge: no capability added; port 8080 needs none (the Service maps 80 to 8080 outside the pod).
  • P1: values keys httpRoute.gateway.{name,namespace,sectionName}, httpRoute.hostnames, listenAddr.
  • P2: make check runs the Go, AD-1 and chart targets, not the image build.
  • P3: prek runs lint-go and lint-chart at commit (against the parallax proposal, to follow the prek.toml convention).
  • P4: ReadHeaderTimeout 10 s, no WriteTimeout.
  • P5: the AD-1 check fails on any require and on a non-empty go.sum.
  • P6: make build-image runs the container read-only, all capabilities dropped, uid 65532, and checks /healthz.
  • P7: Go from the go 1.27.1 line; Helm exactly 4.3.0 from HELM_VERSION, checked by lint-chart.
  • D1 to D16: all 16 detail proposals validated together (target names, one CI job per target, no -race, ci/test-values.yaml, go:embed file at the module root, exit codes, page sentence, defaults).
  • R1: the new jobs become required checks right after the merge; the human runs the gh api command.
  • R2: chart tests use the helm-unittest plugin in charts/scaleway-manager/tests/.
  • R3: Deployment strategy Recreate: never two pods.
  • R4 to R9: cross-compilable Dockerfile, images pinned by digest, IPv6 port parsing, 0.0.0 documented, Go install hint, fixed ClusterRole names accepted.
  • Research: skipped; helm-unittest support for Helm 4.3.0 is settled in Plan.
  • Spec-lint rounds 1 to 4: each criterion rewritten to one reading (HEAD body, signals, log lines, exact FROM lines, port rules, tool hints); the AD-1 check is a tested Go program.
  • Process: markdownlint ignores .memlog.md files.
